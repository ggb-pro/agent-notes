# Agent失败案例如何分析？常见的失败模式有哪些？

> **难度**: 中等 | **分类**: AI Agent理论与框架 | **标签**: AI

## 核心定义
- Agent失败分析的核心是追踪推理链路和工具调用过程，通过日志重放来定位断点。
- 与传统软件Bug不同，Agent失败带有不确定性和涌现性，相同输入可能产生不同结果，需建立概率化的监控体系。

## 机制与原理
- **系统化排查 (5W1H)**：按感知-推理-行动-反馈闭环逐层排查。精确记录异常现象、时间规律、所在环节、涉及模块及复现方法。
- **根因分析树**：将失败现象按核心模块（Prompt构造、LLM推理、工具调用、结果整合）层层拆解，每个分支需配置对应的验证实验。
- **黑盒观察点建立**：针对LLM推理黑盒，收集失败案例按现象聚类，定义特征标签（如“思维固着”、“规划摇摆”）和自动检测规则。
- **常见失败模式**：
  - **推理偏离与死循环**：多轮交互遗忘目标，或陷入固定状态来回跳转（缺少终止条件）。
  - **幻觉污染决策**：基于低相关性检索结果或过时知识编造逻辑自洽的错误信息。
  - **工具调用错误**：参数不匹配、超时，或中间件吞掉异常导致Agent基于错误假设继续推理。
  - **上下文丢失**：随对话历史增长超出Token限制，简单截断导致早期关键信息丢失。
- **监控与评估体系**：
  - **分层指标**：任务完成率（结合转人工频次）、交互效率（平均轮次）、质量指标（用NLI模型做幻觉检测分数）。
  - **双重阈值告警**：单次失败记日志，短时间（如5分钟）失败率超阈值（如20%）才触发告警，过滤偶发噪音。
- **容错与降级机制**：
  - **分层降级**：Agent内部切换保守Prompt -> 系统级切换规则引擎/人工客服 -> 业务级关闭功能入口。
  - **输入输出拦截**：输入层做实体识别与意图校验，输出层强制结构化Schema并增加规则校验。
- **持续改进**：建立结构化失败案例知识库；通过严格控制变量的A/B测试验证优化效果，并做漏斗分析。

## 对比速记
| 维度 | 传统软件Bug | Agent失败 |
| :--- | :--- | :--- |
| **复现性** | 确定性强，相同输入必现相同错误 | 不确定性，相同输入可能结果不同 |
| **调试方式** | 断点单步调试，逻辑清晰 | 黑盒状态，需依赖外部链路追踪和日志重放 |
| **故障根因** | 代码逻辑漏洞 | Prompt约束缺失、LLM采样随机性、工具异常等多点涌现 |
| **监控指标** | HTTP状态码、接口延迟、错误率 | 任务完成率、交互轮次、幻觉检测分数、Token消耗 |

## 代码示例
```java
// 优化后的商品信息检索调用：增加严格校验防幻觉与信息混淆
public ProductInfo searchProduct(String userQuery) {
    // 1. 严格的实体识别
    ProductEntity entity = extractProductEntity(userQuery);
    if (entity.getModel() == null) {
        return askUserToClarify("请问您想了解哪个具体型号？");
    }

    // 2. 精确匹配优先，提高相似度阈值
    List<ProductInfo> results = searchEngine.search(
        entity.getModel(),
        SimilarityThreshold.HIGH  // 阈值提升
    );

    if (results.isEmpty()) {
        return fallbackToManualService();
    }

    // 3. 结果验证：校验返回实体是否与用户需求一致
    ProductInfo bestMatch = results.get(0);
    if (!bestMatch.getModel().equalsIgnoreCase(entity.getModel())) {
        logger.warn("检索结果型号不匹配，用户需求: {}, 返回: {}", entity.getModel(), bestMatch.getModel());
        return askUserToClarify("没有找到完全匹配的商品，您是想了解" + bestMatch.getModel() + "吗?");
    }

    return bestMatch;
}
```

## 工程要点
- **链路追踪可视化**：使用LangSmith等平台串联完整调用链，重点关注Token消耗分布及工具调用前后的变化。
- **自主性与可控性平衡**：根据任务容错度调整自由度。低风险场景（如推荐）可大胆尝试，不可逆操作（如退款、修改库存）必须加人工审核卡点。
- **模型行为漂移监控**：Agent复杂度随迭代急剧上升，需定期抽样对比历史基线，配合完善的版本管理和灰度发布机制以便快速回滚。
- **理性的技术选型**：流程固定的任务直接使用状态机或工作流引擎；Agent更适合处理开放性任务，避免过度设计。
