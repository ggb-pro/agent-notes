# Reflexion机制如何工作？如何通过自我反思提升Agent性能？

> **难度**: 中等 | **分类**: AI Agent理论与框架 | **标签**: AI

## 核心定义
- **定义**：Agent在任务失败后，通过LLM对执行轨迹进行自我反思，生成具体的语言化经验记忆，并在后续尝试中利用该经验优化决策的机制。
- **核心价值**：将隐式的试错过程显式化，利用LLM语言理解能力直接从失败中提取可操作知识，通常3-5次迭代即可解决复杂问题。

## 机制与原理
- **Actor执行**：生成包含完整决策过程的可追溯行动轨迹，为后续反思提供定位依据。
- **Evaluator评估**：提供明确的反馈信号（如测试用例报错的具体行号和堆栈），而非粗粒度的“成功/失败”。
- **Self-Reflection反思**：将任务、轨迹和评估结果输入LLM，强制输出结构化分析：错误定位、原因分析、改进建议。
- **记忆机制**：反思文本通常作为短期记忆直接拼接到下一次执行的Prompt中，而非必须存入向量数据库。
- **性能提升**：一方面避免同类问题重复犯错，另一方面通过文本经验积累加速任务收敛。

## 对比速记
- **vs 传统强化学习 (RL)**：RL依赖数值型奖励，需海量采样拟合价值函数；Reflexion依赖语言化因果分析，能直接定位策略缺陷，极大降低试错成本。
- **vs Few-shot Prompting**：Few-shot是预先准备的静态示例；Reflexion是Agent在实际执行中动态生成、针对当前特定障碍的经验。
- **vs ReAct / CoT**：CoT解决单步推理，ReAct解决推理与行动的交互，Reflexion解决跨轮次的经验学习与记忆积累（三者常组合使用）。

## 代码示例
```java
// 第一次生成的代码（缺少边界检查，导致空输入异常）
public List<String> parseUserInput(String input) {
    return Arrays.asList(input.split(","));
}

// 经过反思后的改进版本（注入了具体的反思经验）
public List<String> parseUserInput(String input) {
    // 反思经验：需要校验空输入，避免后续操作异常
    if (input == null || input.trim().isEmpty()) {
        return Collections.emptyList();
    }
    // 反思经验：分割前应该去除首尾空格，并过滤空白元素
    return Arrays.stream(input.trim().split(","))
                 .map(String::trim)
                 .filter(s -> !s.isEmpty())
                 .collect(Collectors.toList());
}
```

## 工程要点
- **适用场景**：具有明确评估标准且解空间大的任务（如代码生成、SQL生成），不适用于难以客观评估或试错成本极高的任务。
- **反思质量控制**：避免生成过于抽象的反思（如“逻辑不对”），必须提供具体可执行的行动建议（如“遍历前必须检查数组长度”）。
- **上下文长度限制**：历史反思过多时，可采取“仅保留最近几轮”或“语义去重”策略，防止超出Token限制。
- **计算成本管控**：每轮迭代包含完整的执行、评估和反思消耗大量Token，需设定最大迭代次数（如5轮），未解决则降级人工介入。
